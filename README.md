# 逢甲大學建設碩士在職學位學程　第十屆同學看板

逢甲大學 **建設碩士在職學位學程**（MCD）第十屆的班級看板。
對外一律用全名，不用「建碩」「10 屆」這類簡寫。
架構參考 CXO TC8（`cxo-tc8/tc8-9bb41a`），但拆成三個檔案而不是單檔 5000 行。

目前狀態：**版型階段（v0.9）**。
同學名冊與幹部是**真的**（50 人，來自 115 學年度新生名冊）；
公告、活動、資源交流、相簿是**示範內容**；登入是假的。

## ⚠️ 上線前一定要先讀：名冊的隱私模型

**每一個欄位由本人自己決定給誰看**，四級，由寬到嚴：

| 範圍 | 誰看得到 |
|---|---|
| `public` 公開 | 任何人，包含沒登入的訪客 |
| `alumni` 全學程校友 | 跨屆的學長姊學弟妹（**校友會預留**，現在只有一屆＝等同 class） |
| `class` 本屆同學 | 登入的第十屆同學 ← **預設** |
| `private` 只有自己 | 誰都看不到 |

⛔ **預設一律 `class`，不是 `public`。** 同學是把資料交給班上，不是交給網際網路 ——
要公開必須是他自己動手打開，不能是我們幫他決定的。

姓名、組別、幹部職務、休學與否固定公開（名冊要讓大家對照認領自己）。

**但是**：GitHub Pages 是靜態站，**沒有權限這回事**。
公司職稱放在 `private.js`，只要瀏覽器載入了，翻開發者工具就看得到 ——
現在的遮蔽是把「該有的樣子」先做出來，**擋得住隨手看一眼，擋不住想看的人**。

所以在接上 Supabase 之前：

- 網址要當作**非公開**（已加 `noindex`，建議再用亂碼路徑，像 TC8 的 `tc8-9bb41a`）
- **電話與 Email 一律不要加進 `private.js`** —— 那兩個欄位從一開始就只能走後端
- 真正生效的那天 = `private.js` 被刪掉、改由 Edge Function 驗身分才吐

名冊裡有、但**刻意不放進網站**的：學號（個人識別碼）、性別、備註「請假」
（那是新生說明會請假，不是身分，放上來只會被誤讀成「這個人狀態不對」）。

## 屆別與校友會（預留）

學長姊找學弟妹、跨屆媒合，那才是這套東西真正值錢的地方。

等到第十一屆進來才改，每一個 member、每一則公告、每一個可見範圍都要重新長出
cohort 欄位，那時候已經有真實資料，改動成本是現在的十倍。

**加一屆只要三件事**：`COHORTS` 加一筆 → 新同學補 `cohort` 欄位 →
名冊的屆別篩選會自己長出來（只有一屆時自動隱藏）。

## 手機閱讀

在職專班的同學九成用手機看，所以 `≤520px` 那段 media query 不是「順便相容」，
是主要情境，**不要把桌機的密度直接縮小搬過來**：

- 內文 1rem／行高 1.9，`.hint` 從 .78 提到 .82rem
- 觸控目標：chip 40px、按鈕 46px（原本 chip 只有 ~34px）
- `body` 字級**不能低於 16px** —— iOS 聚焦輸入框會自動放大整頁
- 名冊固定一行兩張卡（`1fr 1fr`），不會變成一長條
- `.kv` 定義清單在窄螢幕改上下排，不然標題會被擠成直書
- 行事曆一行放不下時，「上課／不上課」標籤掉到下一行對齊內容
- 編輯表單的「給誰看」選單另起一行，不跟欄位標題擠
- 說明頁的表格包橫向捲動，不撐寬版面

實測 375×812：**14 個畫面全部橫向零溢出**。

## 接 Supabase 的路線

版型驗收過、真名單進來之後才做。順序：

1. **開 Supabase 專案**，建表：
   `members` / `posts` / `signups` / `checkins` / `needs` / `albums` / `photos`
2. **RLS 逐表設定**。原則跟 TC8 一樣：
   - 公開可讀：名冊（不含電話 Email LINE ID）、公告、活動、資源交流
   - 公開可讀的只有「**數字**」：報名幾人、幾個讚 → 用 view `v_post_seats`
   - 要驗身分：誰報名了、聯絡方式、報到定位 → 走 Edge Function
3. **LINE Login**：申請 Channel → Edge Function `auth` 換自家 token
4. **身分認領**：第一次登入從名冊挑自己是誰，幹部核可後綁定
5. **把 `app.js` 的 `db` 換掉**，`BACKEND` 改成 `"supabase"`，刪 `data.js`

### 從 TC8 學到、不要再踩一次的坑

- **PostgREST 是逐欄授權**：`select` 清單裡只要有一欄沒 `grant`，
  整個查詢回 400，不是那一欄變空 —— 全站資料會一起消失。
  新增欄位時要寫「完整清單被拒就退回舊清單」的退路。
- **日期一律指定 `Asia/Taipei`**。前端後端都要。
  資料庫的 `current_date` 走 UTC，台灣早上 8 點前會差一天。
- **`onclick="f('值')"` 裡的字串要用反斜線跳脫**，不能只做 HTML escape，
  也不能改用 `&#39;` —— 瀏覽器會先把實體解回單引號才交給 JS，等於沒防。
- **報到碼不要用 `prompt()` 收**：LINE 內建瀏覽器不會跳出來，直接回 `null`，
  使用者按了完全沒反應。要用頁面內的輸入框。
- **照片上傳前先壓縮**。手機直出一張 5MB，一次聚餐就吃光免費額度。
